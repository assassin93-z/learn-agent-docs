# 第 11 课：人类审批的记忆与历史搜索

<p align="center">中文 &middot; <a href="../../en/lessons/11-memory/">English</a></p>

Python 参考实现区分了稳定事实与过去的对话文本。长期记忆是一份很小的 `MEMORY.md`
快照，只在新会话开始时加入一次。已保存的对话不会直接进入提示词，只有关键字搜索
才会返回长度受限的片段。这两种机制都不会悄悄采集工作区内容。

```sh
pnpm exec tsx lessons/11-memory/demo.ts
pnpm exec vitest run lessons/11-memory
```

离线 demo 使用工作区之外的临时状态目录，显式批准一条虚构事实，并使用第 04 课格式的
虚构对话记录。结束后会删除自己的状态，不需要模型密钥或网络访问。

## 接入方式

创建 `MemoryStore({ stateDir, workspace, approve })`，使用私有、位于工作区之外且
不纳入版本控制的状态目录。它采用第 04 课相同的 `stateDir/sessions/*.json` 纯消息数组
格式。在多用户部署中，状态必须按用户/所有者隔离；共享一个目录就意味着共享记忆
和可搜索的对话集合。

`createMemoryTools(store)` 返回 `remember` 和 `search_sessions`。
`remember` 仍然具有 `confirm` 风险，但其实现对**每一次**实际新增、替换或删除都重新
调用 `approve` 请求审批。回调能看到确切的事实、匹配的旧条目，以及变更后的字符总数。
外层注册表应执行模式层面的硬性规则和归属规则，但不应对这个工具重复询问审批。
绝不能授予它无人值守的批准，也不能把它暴露给子 Agent。第 09 课的子 Agent 排除这个
工具，第 10 课的计划模式也会阻止它。

只在构建新会话的系统提示词时调用 `await store.memorySection()`。它返回不可变的文本，
将这些事实标注为背景信息，而不是指令；当前用户请求和工具权限具有更高优先级。
后续写入只影响下一个会话，不会改变当前快照。总预算为 2000 个字符，
每条事实归一化为一行，单条最多 512 个字符。

状态路径会被规范化，并检查是否与工作区重叠。读取只接受大小受限的普通文件，
拒绝符号链接和具有多个硬链接的别名，并校验记忆/对话记录格式。写入使用唯一的临时文件、
私有文件权限、锁和原子重命名。记忆变更提案在进程内串行处理；如果审批后记忆已经变化，
该提案会被拒绝，而不是悄悄基于新状态重做变更。进程如果在持有 `MEMORY.lock` 时中断，
可能需要操作者检查并删除遗留锁；Agent 不会自行猜测另一个进程的锁是否可以安全删除。

`searchSessions` 要求所有不区分大小写的关键字都匹配到同一条用户或助手消息。
它排除系统提示词和工具结果，跳过无效文件与标签，最多返回五个短片段，并限制检查的文件
数量、目录枚举范围和读取字节数。时间先后排序只在这个受限的候选集合内生效；
达到扫描上限时会显示标记，提示可能还有未纳入的历史记录。搜索命中不会自动写入记忆，
必须另行提出并审批记忆变更。

## 理解自测

解释为什么记忆不等于对话历史；为什么每条事实都需要明确审批；为什么临时任务进度
不应出现在以后每一次提示词中；为什么注入全部历史会增加成本；以及过期审批和并发写入
如何破坏看似简单的本地存储。
