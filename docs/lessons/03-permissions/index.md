# 第 03 课：权限是宿主策略

<p align="center">中文 &middot; <a href="../../en/lessons/03-permissions/">English</a></p>

Python `lesson-03` 增加了三层检查：硬规则、风险分类，最后是人工批准。
TypeScript 在 `PermissionManager` 中保留这个顺序，权限判断不依赖模型
提示词，也不依赖模型声称某个操作“安全”。

## 离线运行

```bash
pnpm exec vitest run lessons/03-permissions
pnpm exec tsx lessons/03-permissions/demo.ts
```

demo 注入批准回调，在临时工作区中检查权限决策，不执行命令、不访问
真实模型服务，也不使用凭据。

## 建议阅读顺序

1. `PermissionDecision` 和 `ApprovalResult`：策略结果是普通的带类型数据。
2. `hardRules`：拒绝工作区外的路径和危险的 shell 模式。
3. `riskOf`：读取是安全操作，副作用需要确认，未知工具也需要确认。
4. `check`：只有硬规则通过后才询问；发生错误或没有批准时都拒绝执行。
5. `permissions.test.ts`：即使用户批准，也不能覆盖硬规则的拒绝。

通过注册表的 `beforeExecute` 钩子连接权限管理器。钩子接收已经校验的
参数，权限回调决定宿主是否可以执行这些参数。对于动态工具，调用者可以
把可信的风险元数据作为第三个参数传给 `check`，或配置 `riskOverrides`。
工具描述本身不是风险策略。

批准结果的结构是 `{ allowed, reason?, remember? }`。只有 `write_file`
可以记住批准，而且仅在当前管理器实例中生效。每条 shell 命令和每次
fetch 请求都要重新检查，已经记住批准的写入也仍然受硬规则约束。
不同用户、工作区、聊天和无人值守任务不能共享同一个管理器。
后续课程会加入按执行主体隔离的管理器，以及无人值守任务的精确授权。

`renderCall` 展示实际参数，而不是模型生成的解释。它会转义终端控制
字符，并限制文件内容预览长度。对于已经取得精确批准的调用者，也可以
单独使用 `hardRules`。受保护的指令路径，以及后续课程的计划模式，
始终属于不能绕过的硬限制。

## 局限

路径检查会在不创建文件的情况下解析已有符号链接，并拒绝具有多个硬链接
的普通文件。shell 拒绝模式只能拦截明显的误操作，无法阻止任意恶意程序。
批准和 `cwd` 都不是操作系统沙箱；已批准的命令仍然可以离开工作区或
访问网络。绝不要把公司工作数据、凭据或个人主目录作为学习工作区。
