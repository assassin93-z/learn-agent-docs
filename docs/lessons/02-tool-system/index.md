# 第 02 课：工具注册表

<p align="center">中文 &middot; <a href="../../en/lessons/02-tool-system/">English</a></p>

本课对应 Python `lesson-02`：用注册的工具定义和统一执行器替代硬编码的
分发表。Agent 循环不再需要知道某一个具体工具如何工作。

## 离线运行

在仓库根目录执行：

```bash
pnpm exec vitest run lessons/02-tool-system
pnpm exec tsx lessons/02-tool-system/demo.ts
```

demo 使用预设回复的模型、临时工作区和注入的 fetch 响应，不会请求真实
模型服务，也不需要凭据。临时文件会在结束后删除。它验证的是编排行为，
不是模型的推理能力。

## 建议阅读顺序

1. `registry.ts`：一份工具定义组合 JSON schema、执行函数和风险元数据。
2. `tools.ts`：注册目录列表、读取、写入、shell 和 fetch 的具体实现。
3. `paths.ts`：创建嵌套目录之前，先解析已有的各级父目录。
4. `agent.ts`：`runTurn` 更新调用者持有的会话，而不是每次重新开始。
5. 测试：参数校验、批准顺序、失败观察结果和输出长度边界。

Python 装饰器会在导入时注册函数。这里的 `registry.register` 是显式调用，
没有导入副作用或隐藏的全局注册表。`schemas` 向模型提供描述信息的防御性
副本；`execute` 解析返回的 JSON，`executeArgs` 则在批准和执行之前完成
参数校验。

支持的 JSON Schema 子集包括对象、数组、标量类型、必填属性、额外属性
规则、枚举值、数组元素，以及常见上下界。它不是完整的 JSON Schema
实现。嵌套校验可以支持后续的计划和 MCP 工具，而且不会把 schema 文本
当作代码求值。
`$ref`、`anyOf`、`oneOf`、`allOf`、`pattern` 和 `format` 等不受支持的
约束**不会被执行**。注册外部工具之前，要审核它的 schema 和实现；
绝不要仅因为 schema 看起来限制严格，就把工具标记为安全。

`runTurn` 会在多个用户任务之间保留历史。assistant 的调用先于对应的
工具结果，调用仍然顺序执行，默认上限是 20 轮模型调用。
本课还不会把会话保存到磁盘，第 04 课才加入这项能力。

## 基础安全边界

与原版第二课不同，非安全工具不能绕过宿主的批准守卫直接运行。
只有显式标记为 `safe` 的工具默认可以执行；`confirm`、未知风险和
`deny` 默认拒绝执行。守卫接收到的是已经校验的参数，而不是模型返回的
原始 JSON。后续权限课会实现可复用的守卫策略。

内置文件工具的路径限制在工作区内，并检查符号链接是否越界。嵌套写入
会先检查已有的每一级父目录，再创建新目录；文件工具会拒绝目录、FIFO、
设备文件和具有多个硬链接的文件。读取或截断之前，还会再次检查已打开的
文件句柄。大文件通过可以提前停止的有界流读取，而不是先完整载入再缩短。
返回结果是长度受限的 Unicode 文本；异常会转为稳定的观察结果，不包含
原始错误路径或模型服务响应体。

shell 命令沿用上一课的有界输出和最小化子进程环境，超时为 30 秒。
fetch 请求的超时为 15 秒，不跟随重定向，而且需要批准。批准不是操作
系统沙箱：已批准的 shell 命令或 URL 仍然可以访问工作区之外的资源。
fetch 不会拒绝私有地址，也不会固定 DNS 解析结果。只批准你明确愿意
信任的目标，不要使用公司服务端点或经过认证的公司工作数据。
